# VCDInsight – Web-Based VCD Waveform Analyzer for SoC Verification

## Overview

VCDInsight is a web-based platform designed to analyze Value Change Dump (VCD) files generated during RTL simulations. It helps identify signal anomalies, monitor signal health, analyze transactions, compare simulation waveforms and generate verification reports.

The platform uses rule-based analysis to generate **PASS, WARNING or FAIL** results. Google Gemini is optionally integrated to provide explanations and summaries of detected findings.

## Key Features

- **VCD File Analysis:** Upload and analyze VCD and ZIP waveform files.
- **Waveform Viewer:** View signal transitions with zoom, search and time cursors.
- **Signal Overview:** Identify signal names, widths, roles and confidence levels.
- **Signal Health Analysis:** Detect X/Z states, stuck signals, glitches and clock/reset issues.
- **Transaction Analysis:** Analyze handshakes, transfers, latency and read-back mismatches.
- **Rule-Based Verification:** Apply eight configurable verification rule templates.
- **Waveform Comparison:** Compare two simulation captures and identify signal mismatches.
- **Final Verdict:** Generate PASS, WARNING or FAIL results based on detected findings.
- **AI-Based Summary:** Use Google Gemini to generate optional explanations of verification findings.
- **Report Generation:** Generate printable technical verification reports.

## How It Works

1. Upload a VCD or ZIP waveform file.
2. The JavaScript parser extracts signal information and waveform transitions.
3. Signal roles are identified automatically.
4. Signal health and transaction analysis are performed.
5. Configurable verification rules check for design violations.
6. An optional second capture can be compared against the first.
7. The verification engine generates a PASS, WARNING or FAIL verdict.
8. A technical report is generated with findings and timestamps.

## Project Architecture

**Frontend:** VCD/ZIP Upload → VCD Parser → Signal Analysis → Transaction Analysis → Rule Checks → Waveform Comparison → Final Verdict → Report Generation

**Optional AI Integration:** Verification Facts → Python Flask Backend → Google Gemini API → AI Summary

The verification verdict is generated by the rule-based engine. AI is used only for optional explanations and summaries.

## Project Modules

1. **Waveform Viewer** – Visualizes signal transitions and detected issues.
2. **Signal Overview** – Displays signal details and automatically detected roles.
3. **Signal Health** – Checks signal activity, X/Z states, glitches and clock/reset behaviour.
4. **Transaction Analysis** – Analyzes handshakes, transfers and latency.
5. **Rules and Checks** – Performs configurable verification checks.
6. **Simulation Comparison** – Compares two waveform captures.
7. **Final Verdict** – Displays verification results and detected findings.
8. **Report Export** – Generates a printable verification report.

## Running the Project Locally

### Frontend

1. Clone the repository:
   ```bash
   git clone https://github.com/Pavand80/VCDinsight.git
   ```
2. Open the project folder in VS Code.
3. Run the frontend using a local development server, such as VS Code Live Server.
4. Open the application in your browser.

### Backend and AI Summary

1. Navigate to the backend folder.
2. Install the required Python dependencies.
3. Configure your Google Gemini API key in the backend environment file.
4. Start the Flask backend.
5. The optional AI summary feature can communicate with the backend when it is running.

**Note:** The frontend waveform parsing and verification analysis run in the browser. The optional AI summary requires the Flask backend to be available.

## Privacy and Data Processing

- VCD files are parsed and analyzed directly in the browser.
- Waveform files are not uploaded to the backend for analysis.
- The optional AI feature sends a small verification summary rather than the complete waveform file.
- The verification verdict does not depend on the AI response.

## Applications

- Verification learning and support for small development teams.

## Current Limitations

- Automatic signal-role detection depends on signal names and waveform behaviour.
- Transaction pairing currently follows request/response order.
- Analysis has been evaluated using six sample RTL designs.
- Physical FPGA board validation has not been performed.
- The public deployment may not provide AI summaries unless the Flask backend is running.
